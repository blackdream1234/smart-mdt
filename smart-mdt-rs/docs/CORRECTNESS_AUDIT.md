# Final Research Correctness Audit

## Executive Summary

This audit reviewed the freeze candidate as a research artifact, not as an
accuracy or performance improvement exercise. It covered the Rust learner,
certified predicate families, SAT/GF(2) backends, path certification, CALS-MDT,
CompactExplain, AXp generation, persistence, command-line and benchmark
boundaries, dataset handling, and the Python evaluation framework.

The audit found reproducible correctness defects. All reproduced code defects
were fixed without changing public function signatures, adding a new learning
algorithm, modifying evaluation figures, or making an unproven algorithmic
change. The corrected code passes all formatting, lint, Rust, Python, report
generation, strict-data, and full-corpus training checks described below.

The repository as a complete thesis artifact is nevertheless **FREEZE
BLOCKED**. The current 7,360-row full benchmark folder was generated by commit
`ce84324`, before the AXp soundness correction. Every row records only eight
final AXp rows. Forty-four of the 46 datasets have more than 20 retained
features, accounting for 7,040 of the 7,360 rows; those rows were evaluated by
the old theorem-mode reference-row fallback rather than an exact completion
solver. The existing numerical tables, figures, PDF, and claims therefore
cannot certify the corrected implementation. They must be regenerated before
the thesis artifact is frozen.

### Corpus checks

Two bounded checks used the real 46-dataset corpus:

1. The release `smart_certified` learner trained at depth 1 and serialized a
   JSON tree successfully for every dataset. The learner ran in theorem mode,
   so a failed final path audit would have returned an error.
2. A read-only executable linked against the release library applied the same
   strict metadata conditions as the benchmark. All 46 datasets passed:
   non-skipped, non-empty retained features, valid labels, label column
   excluded, and zero raw-label, binarized-label, or complement leakage.

An all-row, one-run `smart_certified` benchmark was also attempted. It was
stopped after 35 minutes without a completed output folder. Benchmark output is
buffered until the whole run completes, so this attempt is not counted as
evidence. The runtime increase is caused by replacing the historical
eight-row/fallback AXp calculation with verification of every held-out row.

## Section 1: Confirmed Correctness Properties

### 1.1 Dataset and protocol properties

- `.dl8` loading uses column 0 as the label, excludes it from features,
  binarizes labels consistently with the Python reference, and removes constant
  feature columns.
- Multiclass majority ties select the lowest label, matching Python's first
  maximum. Sparse label values do not cause allocation proportional to the
  maximum numeric label.
- Strict leakage checks detect exact copies of the raw label, the binarized
  label, and the binary complement.
- All 46 corpus datasets pass the corrected strict metadata checks.
- Train/test splitting, pruning splitting, dataset discovery in the benchmark,
  and result ordering are deterministic for the configured seed.

### 1.2 Predicate and certificate properties

- Unary, Horn, AntiHorn, Square2CNF, and Boolean Affine predicates agree with
  their direct row semantics on tested Boolean inputs.
- Horn and AntiHorn certification uses the effective Boolean polarity after
  threshold evaluation, duplicate removal, and tautology normalization.
- Certified Affine predicates are canonical positive `>= 0.5` Boolean
  literals in strictly increasing feature order.
- A single Affine predicate and every complete Affine path use at most 128
  distinct variables, matching the implemented `u128` GF(2) backend.
- Predicate complements partition the tested Boolean domain exactly, including
  the Square2CNF complement and Affine right-hand-side flip.
- Certificate metadata admits only exact
  language/backend/path-certificate tuples, and only when theorem mode is
  active.

### 1.3 Solver properties

- Horn, AntiHorn, and 2-SAT results match brute force over randomized formulas.
- Duplicate literals and tautological clauses do not change satisfiability.
- Zero, out-of-range, and `i32::MIN` variable identifiers fail closed without
  indexing or negation overflow.
- GF(2) Gaussian elimination matches brute force, including duplicate-variable
  cancellation and explicit assumptions.
- No production `unsafe` block is present. The production source scan also
  found no `unwrap()` or `expect()` calls outside test-only code.

### 1.4 Tree, search, cache, and pruning properties

- Every theorem-mode learned tree receives a final independent path audit.
- SmartCertified branches carry independent theory state and may commit to
  different tractable families after an uncommitted split.
- Horn→AntiHorn, Horn→Affine, and other incompatible same-path transitions are
  rejected.
- Greedy, beam, sparse-lookahead, and selective-lookahead outputs respect
  configured depth and node budgets in the regression corpus.
- Branch-and-bound top-k results match exhaustive candidate selection in the
  tested family spaces.
- Cache identity includes dataset, node rows, theory state, depth, budget, and
  configuration. Cache on/off, eviction, and serial/parallel execution preserve
  the selected model in the deterministic tests.
- Class-aware pruning refuses to infer sufficient evidence when an expected
  class is absent from validation support.

### 1.5 Explanation and AXp properties

- The theorem path blocker invokes the actual Horn, AntiHorn, 2-SAT, or GF(2)
  backend for every opposite-class path.
- The theorem checker requires a non-empty Boolean reference domain, matching
  dimensions, in-bounds predicate scope, and in-bounds selected features.
- Returned final-tree AXps are independently checked for sufficiency and
  single-deletion minimality after extraction.
- The exact path solvers match exhaustive Boolean completion in 4,000
  randomized cases across all certified families.
- A 21-feature counterexample confirms that theorem mode does not use the old
  `<= 20` exhaustive/reference-row boundary.
- Verified explanations reject non-Boolean Affine references, malformed tree
  scope, and out-of-range rows instead of issuing a theorem claim or panicking.
- Audience rendering is deterministic and consumes only the verified JSON
  schema.

### 1.6 Persistence, CLI, benchmark, and evaluation properties

- Every predicate family round-trips through deterministic serde JSON without
  changing the tree or predictions. Malformed JSON returns a recoverable error.
- Unknown methods, malformed numeric flags, missing flag values, and unknown
  enum values fail explicitly rather than selecting a default policy.
- The theorem table requires exact method/family/backend metadata, consistent
  path-state/backend sets, all path gates, no empirical fallback, and no
  incompatible cache reuse.
- Empirical `best-certified` rows remain in the empirical partition and are not
  described as forbidden certified predicates.
- Evaluation partitions are cross-checked against `full_results.csv`; missing,
  partial, contradictory, overflowed, stale, or impossible certification
  evidence fails closed.
- Inferential statistics operate on 46 independent dataset blocks after
  averaging runs and depths within each dataset. Holm correction covers the
  configured family of method-by-metric hypotheses.
- Seeded paired bootstrap output and deterministic report tables are reproduced
  byte-for-byte by the evaluation tests.

## Section 2: Detected Bugs

### A01 — Critical: theorem AXp checks used an empirical fallback

- **Description:** Theorem mode could declare a weak AXp certified without
  checking all Boolean completions.
- **Root cause:** `weak_axp_check` exhaustively enumerated only when the query
  had at most 20 features. Larger or non-Boolean inputs fell through to rows
  present in the reference dataset while retaining theorem-certified metadata.
  No production path-blocking solver was implemented.
- **Affected modules:** `explain/weak_axp.rs`, `explain/path_blocking.rs`,
  `explain/final_tree.rs`, `explain/verified.rs`, and benchmark AXp reporting.
- **Reproducer:** A one-row, 21-feature Boolean domain contains only all-zeroes;
  a unary stump has an unseen `x0=1` opposite-class completion. The old checker
  accepted the empty feature set.
- **Fix:** Implement exact opposite-leaf encodings and dispatch to Horn,
  AntiHorn, 2-SAT, or GF(2); reject non-Boolean theorem domains; independently
  recheck final sufficiency and minimality.
- **Regression:** `certified_path_blocking_handles_more_than_twenty_boolean_features`,
  `certified_path_solvers_match_exhaustive_boolean_completion_randomly`, and
  `theorem_check_rejects_a_non_boolean_domain_even_for_a_boolean_query_row`.

### A02 — High: non-theorem execution could claim theorem certification

- **Description:** Empirical completion checking with `theorem_mode=false`
  could still return `metadata.theorem_certified=true`.
- **Root cause:** `CertificateMetadata::new` validated only enum values and did
  not include `theorem_mode` in the certified flag.
- **Affected modules:** `logic/certificate.rs` and all explanation metadata
  consumers.
- **Reproducer:** Run the 21-feature one-row example from A01 with theorem mode
  disabled. The finite-row result is empirical but previously carried a
  theorem flag.
- **Fix:** Gate every positive theorem certificate on `theorem_mode`.
- **Regression:** `empirical_completion_fallback_never_claims_theorem_certification`
  and the non-theorem case in
  `mismatched_certificate_metadata_triples_are_not_theorem_certified`.

### A03 — Critical: advertised certificate shape did not match backend semantics

- **Description:** Malformed Horn, AntiHorn, or Affine predicates and
  over-capacity GF(2) paths could be certified even though the selected backend
  rejected or could not represent them.
- **Root cause:** Certification trusted the enum variant. Horn polarity was
  counted before Boolean threshold normalization; Affine canonical form and the
  backend's 128-variable capacity were not audited; cumulative path scope was
  not tracked.
- **Affected modules:** `logic/predicate.rs`, `logic/path_theory.rs`,
  `tree/learner.rs`, and the GF(2) explanation boundary.
- **Reproducer:** Two negated `x < 0.5` literals appear negative in wrapper
  polarity but normalize to two positive Boolean literals, violating Horn. A
  129-variable Affine predicate or a path with 64+65 distinct Affine variables
  exceeded the `u128` backend.
- **Fix:** Normalize effective Boolean polarity, canonicalize Affine shape,
  limit each predicate to 128 variables, and accumulate distinct variables
  independently on every path, including unary features before and after
  Affine commitment.
- **Regression:** `structural_clause_shape_uses_effective_boolean_polarity`,
  `gf2_certification_enforces_per_predicate_and_path_variable_limits`, and
  `malformed_structural_predicates_cannot_claim_certification`.

### A04 — Critical: certificate tables admitted inconsistent metadata

- **Description:** Individually allowed enum/text values could be combined into
  an impossible certificate and enter theorem output.
- **Root cause:** Rust certificate construction, Rust theorem-table filtering,
  and Python evaluation used independent whitelist membership rather than
  exact tuple and path-state correspondence.
- **Affected modules:** `logic/certificate.rs`, `eval/report.rs`,
  `evaluation/certification.py`, and theorem/empirical partition generation.
- **Reproducer:** Examples include `Affine + TwoSat + AffineGf2`, a unary method
  labeled Horn, or a path state whose recorded backend belongs to another
  state. Partial textual evidence also passed.
- **Fix:** Enforce exact family/backend/certificate mappings, exact
  state-derived path backend sets, non-empty unique components, all hard path
  gates, and complete textual evidence. Legitimate uncommitted constant or
  unary-only paths remain valid.
- **Regression:** `mismatched_certificate_metadata_triples_are_not_theorem_certified`,
  `theorem_filter_requires_allowed_backend_and_method`,
  `cals_theorem_filter_requires_the_complete_audit_boundary`,
  `test_certification_rejects_mismatched_whitelisted_certificate_tuple`, and
  the single-family uncommitted-path parameter cases.

### A05 — High: theorem-mode learning and `best-certified` reporting could cross the path boundary

- **Description:** A completed greedy tree could avoid a final theorem audit,
  and the mixed per-node `best-certified` policy was reported as Unary/Horn
  theorem execution.
- **Root cause:** Certification was assumed from candidate-level selection and
  declared benchmark defaults instead of validating the final tree and policy.
- **Affected modules:** `tree/learner.rs`, `eval/benchmark.rs`, CLI training, and
  evaluator method configuration.
- **Reproducer:** A greedy per-node tree with a Horn root and Affine child was
  previously constructible under theorem reporting. A `best-certified` row
  inherited Unary/StructuralHorn metadata.
- **Fix:** Audit every final theorem tree, reject mixed-path output, force
  `best-certified` to empirical mode and `EmpiricalMixed`, and support it
  explicitly in the evaluator's empirical partition.
- **Regression:** `theorem_mode_rejects_a_greedy_per_node_tree_with_an_incompatible_path`,
  `theorem_mode_rejects_empirical_and_tuned_policies`, CLI validation tests,
  and evaluator `best-certified` partition tests.

### A06 — High: SAT normalization and malformed identifiers were unsafe

- **Description:** Duplicate literals changed Horn/AntiHorn acceptance;
  tautologies could be rejected; malformed variables could index outside solver
  graphs; AntiHorn negation of `i32::MIN` overflowed.
- **Root cause:** Structural checks ran on raw clauses and AntiHorn flipped
  polarity before validating signed identifiers.
- **Affected modules:** `sat/horn_sat.rs`, `sat/antihorn_sat.rs`,
  `sat/two_sat.rs`, and shared SAT helpers.
- **Reproducer:** `[1,1]`, `[-1,-1]`, `[1,-1,2]`, variable `0`, variable
  `num_vars+1`, and `i32::MIN`.
- **Fix:** Validate first, deduplicate clauses, discard tautologies, and fail
  closed for malformed identifiers in every solver and brute-force reference.
- **Regression:** `duplicate_literals_do_not_change_horn_or_antihorn_satisfiability`
  and `malformed_sat_variable_ids_are_rejected_without_panicking`.

### A07 — High: malformed AXp inputs could panic

- **Description:** Non-theorem AXp checks and deletion extraction indexed
  mismatched instances, out-of-range selected features, invalid tree scope, or
  an out-of-range row.
- **Root cause:** Dimension and scope validation existed only on part of the
  theorem path and occurred after some indexing.
- **Affected modules:** `explain/weak_axp.rs`,
  `explain/axp_deletion.rs`, and `explain/verified.rs`.
- **Reproducer:** Pass feature 7 to a one-column domain, an empty instance to a
  one-column domain, a tree using feature 7, or `row == domain.rows()`.
- **Fix:** Apply common fail-closed validation before both theorem and empirical
  branches; return rejected metadata from deletion extraction rather than
  indexing.
- **Regression:** `weak_axp_rejects_malformed_empirical_inputs_without_panicking`,
  `axp_deletion_rejects_bad_row_and_tree_scope_without_panicking`, and
  `out_of_bounds_tree_scope_is_rejected_without_prediction_panic`.

### A08 — High: the public JSON persistence functions did not persist models

- **Description:** `to_json` emitted Rust debug text rather than JSON and
  `from_json` always returned an error.
- **Root cause:** Both functions were placeholders while being exposed as the
  persistence API and used by CLI output.
- **Affected modules:** `tree/serialize.rs` and train CLI output.
- **Reproducer:** Serialize any internal tree and attempt to parse it as JSON or
  load it with `from_json`.
- **Fix:** Add deterministic serde DTOs for every tree, predicate, literal, and
  threshold operation.
- **Regression:** `every_predicate_family_round_trips_as_json_without_prediction_changes`,
  `malformed_json_returns_a_recoverable_error`, and randomized fuzz round-trips.

### A09 — High: label preprocessing diverged from the Python protocol and could allocate catastrophically

- **Description:** A multiclass frequency tie selected the highest label rather
  than the lowest, and a sparse label such as `i32::MAX` requested a vector
  proportional to the label value.
- **Root cause:** Rust `max_by_key` retains the last maximum and dense counting
  used the maximum numeric label as capacity.
- **Affected modules:** `data/dataset.rs`.
- **Reproducer:** Equal counts for labels 0 and 2; or observed labels
  `{0, 1, i32::MAX}`.
- **Fix:** Count observed non-negative labels in an ordered sparse map and
  select the first label with maximum count.
- **Regression:** `python_binarization_equivalence_cases` includes tie and
  sparse extreme-label cases.

### A10 — Critical: strict leakage checks missed target-equivalent features

- **Description:** A raw target copy or binary complement could survive strict
  checks and produce invalid research accuracy.
- **Root cause:** The detector compared only against the post-binarization label
  with the same polarity.
- **Affected modules:** `data/dataset.rs`, benchmark warnings, and evaluation
  metadata auditing.
- **Reproducer:** A feature equal to raw two-class labels before remapping, or
  a feature equal to `1 - binary_label`.
- **Fix:** Audit raw label, binarized label, and binary complement; propagate
  the finding through strict rejection and report metadata.
- **Regression:** `raw_two_class_label_copy_is_detected_before_binarization_can_hide_it`,
  `inverse_label_feature_is_detected_and_rejected_by_strict_checks`, and
  evaluator leakage contradiction/count tests.

### A11 — High: class-aware pruning treated an absent class as sufficient evidence

- **Description:** A validation subset with no minority-class observations
  could permit a constant replacement even though the profile requires
  per-class support.
- **Root cause:** The support guard iterated only keys present in the validation
  support map, so a missing expected class passed vacuously.
- **Affected modules:** `tree/prune.rs` and learner pruning integration.
- **Reproducer:** Supply validation rows containing only the majority class
  while the grow/original dataset contains both classes.
- **Fix:** Carry the expected class universe from the original training data
  into pruning and treat missing support as zero.
- **Regression:** `missing_expected_class_is_insufficient_validation_evidence`
  and the existing balanced/minority-recall pruning guards.

### A12 — Medium: configured resource and pruning boundaries were silently ignored

- **Description:** Greedy search could exceed `node_budget`; a zero node budget
  was accepted; an invalid pruning fraction was swallowed and silently disabled
  pruning.
- **Root cause:** Node-budget enforcement existed only in global search and the
  pruning split error was converted with `.ok()`.
- **Affected modules:** `tree/learner.rs`.
- **Reproducer:** Greedy training with budget 3 or 5 on a splittable dataset;
  node budget 0; pruning fraction outside `(0,1)`.
- **Fix:** Deterministically allocate subtree budgets to both children, reject
  zero, propagate invalid pruning configuration, and intentionally skip only
  the documented too-small-data case.
- **Regression:** `greedy_respects_a_finite_total_node_budget` and
  `invalid_pruning_fraction_is_rejected_instead_of_silently_disabling_pruning`.

### A13 — High: benchmark AXp metrics and success counts did not describe the dataset

- **Description:** A field named mean AXp length used only the first eight test
  rows, making results order-dependent. Certified-rate and success columns
  represented one row-level Boolean rather than the audited AXp population.
- **Root cause:** A fixed `maximum_rows=8` smoke shortcut was retained in the
  full benchmark and reused as formal output.
- **Affected modules:** `eval/benchmark.rs` and evaluation certification inputs.
- **Reproducer:** A dataset whose ninth row needs a longer AXp produced the same
  reported mean as the first-eight prefix.
- **Fix:** Extract and verify AXps for every test row; report the actual success
  count for admitted rows and `NaN` rather than a fabricated 0% for rejected
  rows.
- **Regression:** `dataset_axp_metric_includes_rows_after_the_eighth_prefix`,
  final-tree sufficiency/minimality checks, and CSV output tests.

### A14 — Medium: CLI and benchmark parsing silently changed requested experiments

- **Description:** Unknown training methods became `best-certified`, unknown
  benchmark methods were skipped, malformed numerics fell back to defaults, and
  unsupported enum values selected catch-all branches.
- **Root cause:** Default match arms and `parse().ok()` were used without a
  prior validation boundary.
- **Affected modules:** `main.rs` and `eval/benchmark.rs`.
- **Reproducer:** `--method typo`, `--methods unary,typo`, malformed depths,
  `NaN` pruning values, or an unknown score/search profile.
- **Fix:** Validate required values, integer/finite-number arguments, lists,
  enums, and method names before dispatch; return `InvalidInput`.
- **Regression:** `train_rejects_an_unknown_method_instead_of_changing_policy`,
  `benchmark_rejects_an_unknown_method_instead_of_silently_skipping_rows`, and
  `malformed_numeric_and_enum_arguments_are_rejected`.

### A15 — Medium: debug output could claim a node it never inspected

- **Description:** Non-root `--depth` and `--node-path` values were copied into
  output even though candidate generation always evaluated the root.
- **Root cause:** The debug command had no path traversal implementation but did
  not reject unsupported location flags.
- **Affected modules:** `eval/debug_candidates.rs`.
- **Reproducer:** Request depth 2/path `LR` and compare counts with the root;
  output was identical but labeled `LR`.
- **Fix:** Explicitly support only depth 0/path `root` and reject other values
  until real traversal exists.
- **Regression:** `unsupported_debug_node_path_is_rejected_instead_of_echoing_root_results`
  and `unknown_debug_method_is_rejected`.

### A16 — Low: CSV escaping mutated audited text

- **Description:** Embedded quotes were replaced with apostrophes, changing
  configuration, reason, or predicate text.
- **Root cause:** The CSV helper used a lossy substitution instead of RFC-style
  doubled quotes.
- **Affected modules:** benchmark and debug CSV writers.
- **Reproducer:** Serialize `a"b`; old output contained `a'b`.
- **Fix:** Double embedded quotes inside a quoted field.
- **Regression:** `csv_escaping_preserves_embedded_quotes`.

### A17 — Critical: inferential statistics used pseudoreplicated observations

- **Description:** Runs and depths from the same dataset were treated as
  independent Wilcoxon and bootstrap pairs, inflating sample size and
  significance.
- **Root cause:** Pairing was performed on
  `(dataset, run, depth)` rather than averaging repeated observations within
  the independent dataset block.
- **Affected modules:** `evaluation/statistics.py`,
  `evaluation/significance.py`, executive summaries, and report templates.
- **Reproducer:** CALS vs CompactExplain mean AXp used 920 pairs and reported
  approximately `p=3.505e-05`. Correct blocking uses 46 pairs and gives raw
  `p=0.0581599766151`, 95% bootstrap CI
  `[-0.175815217391, 0.0471467391304]`.
- **Fix:** Aggregate runs and depths within `(dataset, method)` before
  descriptive or inferential statistics.
- **Regression:** dataset-block sample-size, repeated-pair completeness, and
  weighted-duplication tests in `evaluation/tests/test_statistics.py`.

### A18 — High: multiple testing was not controlled

- **Description:** Conclusions used unadjusted p-values across the configured
  method-by-metric hypothesis family.
- **Root cause:** Pairwise tests were reported independently without family-wise
  correction.
- **Affected modules:** `evaluation/significance.py`, tables, templates, and
  conclusions.
- **Reproducer:** The corrected CALS vs CompactExplain AXp raw p-value is
  `0.0581599766151`; its Holm-adjusted value is `0.11631995323`.
- **Fix:** Apply Holm's step-down correction across all configured hypotheses
  and use the adjusted values for significance language.
- **Regression:** Holm monotonicity/order tests and end-to-end significance
  output assertions.

### A19 — Critical: evaluator certification evidence failed open

- **Description:** Missing or partial textual tuples, stale theorem partitions,
  contradictory leakage fields, and oversized integer counts could still
  produce a passing audit.
- **Root cause:** Optional evidence was treated as sufficient; partition checks
  omitted important columns; integer checks converted through imprecise float;
  one leakage field shadowed the other.
- **Affected modules:** `evaluation/certification.py`,
  `evaluation/utils.py`, and report admission.
- **Reproducer:** Remove all tuple columns; alter only theorem-table path fields;
  set count 0 with suspicious flag true; or use
  `9223372036854775808`, which previously wrapped to a negative `int64`.
- **Fix:** Require complete tuples for theorem admission, compare critical
  fields and metrics to canonical full results, parse exact decimal integers
  within bounds, cross-validate leakage evidence, and count leaking features
  rather than affected datasets.
- **Regression:** Missing/partial tuple, stale partition, leakage contradiction,
  total leakage, and integer-overflow tests in
  `evaluation/tests/test_analysis.py`.

### A20 — High: evaluator completeness and diagnostic domains were under-specified

- **Description:** Incomplete method grids, partial diagnostics, impossible
  negative/fractional counts, out-of-range rates, a supported
  `best-certified` method, and reports without a configured comparison were
  handled incorrectly.
- **Root cause:** Validation checked presence/finite conversion but not exact
  key coverage or value domains; empty significance frames had no schema.
- **Affected modules:** `evaluation/io.py`, `evaluation/config.py`,
  `evaluation/significance.py`, and table generation.
- **Reproducer:** Remove a method from one dataset/run/depth cell, omit one
  diagnostic key, set node count to `-7.5`, load `best-certified`, or build a
  report containing only `smart_certified`.
- **Fix:** Enforce a complete common grid, exact diagnostic key partitions,
  non-negative integral counts, bounded rates, known method support, and a
  schema-complete empty significance table.
- **Regression:** Grid, key-coverage, diagnostic-domain, method-loading, and
  no-pair end-to-end report tests.

## Section 3: Potential Risks

These are documented assumptions or future hardening opportunities, not
reproduced correctness defects in the audited protocol.

1. **Stale numerical artifacts:** This is the current freeze blocker. Structural
   evaluation can parse the old 7,360 rows, but that does not make their AXp
   evidence valid for the corrected code.
2. **All-row AXp cost:** Correct full-dataset AXp metrics are much more expensive
   than the historical eight-row shortcut, especially for datasets with 989 to
   1,276 retained features. Full regeneration needs an explicit compute budget
   and should not be interrupted.
3. **Recursive depth:** 2-SAT SCC traversal, tree traversal, and recursive JSON
   conversion can exhaust the process stack on adversarially deep inputs.
   Normal learner depth and node budgets keep repository experiments far below
   this boundary.
4. **Low-level index contracts:** `ColumnMajorMatrix::get`, direct prediction
   helpers, and GF(2) constructors retain documented row/feature and
   `<128` index preconditions. Public high-level learner and explanation
   boundaries now validate their inputs.
5. **Resource exhaustion:** Supplying solver variable counts or serialized trees
   that are intentionally enormous can exhaust memory even when indices are
   syntactically valid.
6. **Duplicate dataset stems in debug discovery:** If separate directories
   contain the same filename stem, the root-only debug lookup does not define a

7. **Leakage scope:** The strict audit detects exact raw, binary, and complement

   distributions, while inferential tables use independent dataset blocks.

9. **Cliff's delta:** The report includes standard independent-sample Cliff's
   delta as a distributional effect size alongside paired Cohen's d. It should
   not be interpreted as a paired estimator.
10. **Expected method manifest:** Grid validation proves completeness among
    methods present in the input. It cannot detect a method omitted from every
    row unless an external expected-method manifest is supplied.
11. **CSV evidence boundary:** Aggregate language/path-state/backend sets can
    detect inconsistent metadata but cannot reconstruct every tree path.

    post-hoc path proof is required.
12. **Timing interpretation:** Method execution order is fixed and timings are
    local-machine measurements. They are not portable performance guarantees.
13. **Corpus inference:** Dataset-block confidence intervals and tests are
    correct for the configured corpus analysis, but generalization beyond the
    selected 46 datasets remains a scientific sampling assumption.
