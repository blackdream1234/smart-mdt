# Historical AXp Runtime Investigation and Freeze-Run Analysis

> **Caching experiment not included in the freeze candidate.** Commit
> `d75391d` demonstrated that repeated domain scans dominated AXp runtime, but
> the freeze task explicitly prohibited performance optimization. Commit
> `ac4f181` therefore reverted that experiment. The profiling and equivalence
> evidence below are retained as historical diagnostics only. The completed
> benchmark was generated by the non-caching correctness commit `1fbfa30`.

This note documents the reverted experiment and the completed full benchmark
run.

---

## 1. The Reverted Experiment

**Commit:** `d75391d` — *Cache tree/domain-invariant facts in weak-AXp checking*

**Files:** `src/explain/weak_axp.rs`, `src/explain/axp_deletion.rs`,
`src/explain/final_tree.rs`

**Type:** correctness-neutral performance experiment. It was reverted to comply
with the freeze task and is not part of the final benchmark implementation.

---

## 2. Why the Change Was Needed

### Symptom

After the audit fixes (in particular A01/A13, which replaced an unsound 8-row
AXp shortcut with exact per-row verification), the strict full-corpus benchmark
became extremely slow. A one-run pass could not finish 46 datasets in 34 hours,
and the ten-run official benchmark was projected at roughly **20 days**. A
pre-audit run of the same command had finished in under 5 hours, so the
slowdown needed explanation.

### Root cause

The abductive-explanation (AXp) code checks whether a set of features is a weak
AXp with `weak_axp_check`. Two of the quantities it computed on **every call**
do not depend on the call arguments:

- `backend_meta(tree, ...)` — depends only on the tree.
- `is_binary_domain(domain)` — a full scan of the whole reference matrix
  (`rows × features`), independent of the instance or selected features.

The deletion algorithm calls `weak_axp_check` once per feature, per row, and the
benchmark repeats this for every held-out row of every dataset. As a result the
same fixed domain was rescanned millions of times.

### Measured impact

Profiling on `letter.dl8` (20 000 rows, 224 features, depth-5 tree), for 30 rows
of AXp extraction:

| Component | Time | Share |
|---|---:|---:|
| `is_binary_domain` / `is_binary_instance` (redundant rescan) | 112.03 s | **99.8 %** |
| certified solve (Horn / AntiHorn / 2-SAT / GF(2)) — the necessary work | 0.17 s | 0.1 % |
| `backend_meta` | 0.03 s | 0.0 % |
| `count_opposite_leaves` | 0.003 s | 0.0 % |

The genuinely required, theorem-mandated work (the certified solve) was only
**0.1 %** of the time. The redundant domain rescan was **99.8 %**. The slowdown
was therefore **not** an inherent cost of the correctness fix; it was accidental
repeated work.

## 3. How the Fix Works

The two invariant facts are computed **once per tree/domain pair** and stored in
a small `AxpCheckContext`:

```rust
pub(crate) struct AxpCheckContext {
    meta: CertificateMetadata,   // backend_meta(tree, theorem_mode)
    domain_is_binary: bool,      // is_binary_domain(domain)
}
```

`extract_final_tree_axps` builds one context for the whole call; each row and
each feature-deletion trial reuses it through `*_with_context` variants. The
public functions `weak_axp_check` and `extract_axp_deletion` keep identical
signatures and behavior — they build the context internally — so no existing
caller or test is affected.

**Result:** for the 30-row `letter.dl8` case, AXp extraction dropped from
**112.26 s to 0.062 s** (~1800×), with the identical certified result
(`valid=30, minimal=30`).

---

## 4. Why the Output Is Unchanged (Correctness)

The cached values are the exact values the old code recomputed on every call, so
every certification decision, AXp, and reported metric is identical. This was
confirmed three independent ways:

1. **7 new equivalence unit tests** — the cached and uncached paths return
   byte-identical `WeakAxpResult` / `AxpResult` across certified success,
   non-Boolean-domain rejection, dimension mismatch, out-of-bounds row, and
   empirical mode.
2. **Full test suite:** 161 → 168 tests, all passing unchanged
   (`cargo fmt --check`, `clippy -D warnings`, `cargo test` all green).
3. **End-to-end A/B benchmark** (3 datasets × 8 methods, before-fix vs
   after-fix binary): **0 differences across all 88 non-timing columns** —
   accuracy, tree structure, `theorem_certified`, backend, path state,
   `axp_valid_rate`, `axp_minimal_rate`, and all pruning/search diagnostics.
   The only columns that differed (`predicate_mask_cache_hits/misses`) were
   shown to vary the same way between two runs of the *same* binary, i.e. they
   are pre-existing run-to-run noise unrelated to this change.

## 5. Analysis of the Last Run

**Artifact:** `rust_results_manual_check/`
**Command:** `benchmark --data ../data --depths 5,7 --runs 10
--methods unary,horn,antihorn,square2cnf,affine,smart_certified,cals,cals_compact_explain
--strict-data-checks`

### 5.1 Completeness

- **7360 rows** = 46 datasets × 10 runs × 2 depths × 8 methods (920 rows per
  method). All datasets processed under strict data checks; none skipped.
- Post-audit schema (includes `test_rows`, `final_axp_rows`, per-row AXp
  evidence).

### 5.2 Certification (independent verification)

An independent re-implementation of the certification boundary was run over all
7360 rows. Result: **PASS on every row**.

| Audit item | Count | Status |
|---|---:|---|
| theorem-certified rows | 7360 / 7360 | pass |
| empirical rows | 0 | pass |
| forbidden predicates | 0 | pass |
| feature–label leakage | 0 / 46 | pass |
| path violations | 0 | pass |
| cached-subtree violations | 0 | pass |
| empirical fallbacks | 0 | pass |
| AXp evidence violations | 0 | pass |
| full-row AXp violations | 0 | pass |
| skipped datasets | 0 / 46 | pass |

Every theorem row carries a complete, consistent
language/backend/path-certificate tuple, `theorem_mode_used = true`,
`path_certified = true`, and full-held-out-row AXp validity and minimality
(`axp_valid_rate = axp_minimal_rate = 1.0`).

### 5.3 Benchmark warnings (all benign)

49 warnings were emitted; none indicate a certification problem, and there is
**no feature–label leakage**:

- `high_accuracy_tiny_tree` (40) and `suspicious_majority_rate` (1): all on
  `winequality-red-bin`, which is ~99.4 % one class. A tiny tree trivially
  scores high there — a data-quality note, not a modelling error.
- `method_all_constant_trees` (4) and `method_all_zero_axp` (4): on
  `balance-scale-bin`, `seismic_bumps-bin`, and `winequality-red-bin`, where a
  method (mostly CompactExplain, via aggressive certified pruning) returns a
  constant tree, which by definition has AXp length 0.

### 5.4 Results by method (means over 46 dataset blocks)

| Method | Accuracy | Tree nodes | Mean AXp |
|---|---:|---:|---:|
| Unary | 0.859 | 53.2 | 3.93 |
| Horn | 0.860 | 51.2 | 5.14 |
| AntiHorn | 0.860 | 51.5 | 5.55 |
| Square2CNF | 0.859 | 50.8 | 6.36 |
| Boolean Affine / GF(2) | 0.854 | 53.1 | 7.90 |
| SmartCertified | 0.860 | 50.7 | 4.18 |
| **CALS-MDT** | **0.865** | **12.7** | 2.98 |
| CompactExplain | 0.860 | **11.1** | **2.72** |

### 5.5 Statistical conclusions (Holm-adjusted, dataset-block bootstrap)

- **CALS-MDT** has the highest accuracy (0.865) and about **4× smaller trees**
  than the single-family certified methods (12.7 vs ≈51 nodes). SmartCertified
  vs CALS-MDT on tree nodes: −38.0 nodes (Holm p = 4.6e-8, large effect).
- **CompactExplain** gives the smallest trees (11.1) and shortest AXp (2.72).
  Its mean accuracy is 0.0047 lower than CALS-MDT
  (95% bootstrap CI [−0.0073, −0.0022], Holm p = 0.011,
  paired Cohen's d = −0.523, medium effect), while its mean fit time is lower.
- Accuracy differences among the single-family certified methods are small; the
  clear separation is in **model size and explanation length**, where the
  multivariate methods win decisively.

### 5.6 Interpretation

Descriptively, CALS-MDT and CompactExplain produce much smaller trees
(approximately 11–13 nodes) than the single-family certified methods
(approximately 51–53 nodes). CALS-MDT has the highest mean accuracy in this
corpus; CompactExplain's mean accuracy is close to the single-family methods
while its trees and AXps are shorter. These statements describe the configured
46-dataset corpus and do not assert generalization beyond it.

The completed run is stamped with benchmark commit `1fbfa30`, which contains
the correctness fixes and no performance optimization. Its immutable bytes are
archived as `rust_results_final_freeze_r10_1fbfa30/`. The independent

experiment was not used to generate or admit this artifact. The final decision
